# oauth2-proxy-internal

A second oauth2-proxy instance that gates the **syncthing** web GUI with Authelia
SSO. Unlike the public `oauth2-proxy` (which fronts the homepage dashboard and
**bypasses auth for internal clients** via `trusted_ips`), this instance has **no
internal-network bypass**: every client, LAN included, must authenticate, and
only members of the **`syncthing-admins`** group are admitted.

## How it fits together

```
client ──► traefik-gateway (kube-system, websecure/HTTPS, *.msng.to wildcard cert)
       ──► HTTPRoute (syncthing.msng.to)
       ──► oauth2-proxy-internal  ──(Authelia OIDC SSO + syncthing-admins)──►
       ──► syncthing GUI (ClusterIP :8384, no built-in auth, NetworkPolicy-locked)
```

- syncthing's GUI has **no built-in auth**; access is gated entirely here, and a
  NetworkPolicy restricts `:8384` to this namespace.
- `external-dns-internal` resolves `syncthing.msng.to` to the gateway VIP
  (10.69.80.100) in Unifi DNS.
- The Authelia OIDC client `oauth2-proxy-internal` lives in `auth-system/values.yaml`.

## Client secret

The `client-secret` in `oauth2-proxy-internal-secrets` is auto-generated by
mittwald on first sync. Authelia needs a **bcrypt hash** of that value, which is
produced automatically: this Secret grants reflection into `auth-system`, and a
PreSync job there mirrors it in, hashes it, and writes it to the Secret Authelia
mounts. No hash is committed to git and no manual bootstrap step is required.

See `k8s/platform/auth-system/files/oidc-client-secrets/README.md` for the wiring
and for how to rotate this secret.
