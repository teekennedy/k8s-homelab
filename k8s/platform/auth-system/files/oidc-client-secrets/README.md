# Authelia OIDC client secret sync

Keeps the `authelia-oidc-client-secrets` Secret in step with the plaintext client
secrets that mittwald secret-generator creates in each consuming app's own
namespace, so a bcrypt hash never has to be generated or committed by hand.

## Why this exists

Authelia wants a *bcrypt hash* of each confidential client's secret, mounted as a
file. The plaintext is generated in the app's namespace, because the upstream
oauth2-proxy chart wants `client-id`/`client-secret`/`cookie-secret` together in
one Secret. Bridging those two facts used to be a manual ritual: read the
generated value, run `authelia crypto hash generate bcrypt`, paste the hash into
`values.yaml`, commit, push, sync. This job does it instead.

## Adding a new OIDC client

1. In the app's chart, on the Secret that mittwald generates `client-secret` into,
   grant reflection to this namespace:

   ```yaml
   annotations:
     reflector.v1.k8s.emberstack.com/reflection-allowed: "true"
     reflector.v1.k8s.emberstack.com/reflection-allowed-namespaces: auth-system
   ```

2. In `k8s/platform/auth-system/values.yaml`, add the client under
   `authelia.configMap.identity_providers.oidc.clients` as usual, with

   ```yaml
   client_secret:
     path: /secrets/authelia-oidc-client-secrets/<client_id>
   ```

3. Add one line to `oidcClientSecrets.clients`:

   ```yaml
   <client_id>: <app-namespace>/<app-secret-name>
   ```

Commit and push. That's the whole integration — no hash, no second pass.

Steps 2 and 3 are cross-checked at render time: a client with no source entry, or
a source entry with no client, fails `helm template` in CI with a message naming
the missing side. You cannot half-wire a client and find out later.

## How it runs

An ArgoCD PreSync hook on the auth-system Application. Each run:

1. Creates a reflector "pull" Secret per client (`oidc-client-mirror-<client_id>`,
   annotated `reflects: <ns>/<name>`) and waits for reflector to populate it.
   Mirrors are created by the job rather than templated, so ArgoCD has nothing to
   fight over and the job needs no cluster-wide secret read.
2. Verifies each stored hash against its plaintext with `bcrypt.checkpw` and only
   re-hashes on a mismatch. bcrypt is salted, so hashing unconditionally would
   rewrite the Secret and restart Authelia on every sync.
3. Prunes keys and mirrors for clients that are no longer configured.
4. Restarts Authelia only when an already-present hash changed — i.e. a rotation.
   Adding or removing a client changes Authelia's ConfigMap, and the chart's own
   `authelia.com/checksum-config` annotation rolls the Deployment for that.

Because it's PreSync, a plaintext that never arrives fails the hook and blocks the
sync: Authelia's ConfigMap is never advanced to reference a client whose hash is
missing, and the running pods keep serving the previous config. That is what makes
it safe for auth-system to sync before the app chart that owns the plaintext —
ArgoCD's retry backoff picks it up once the app's namespace lands.

The target Secret is deliberately not templated by the chart. This job owns it
outright (the same arrangement as `authelia-oidc-jwks`), which stops ArgoCD from
applying an empty `data: {}` over the live hashes partway through a sync.

## Rotating a client secret

Delete the key and let mittwald regenerate it, then sync auth-system:

```sh
kubectl -n <app-namespace> patch secret <app-secret-name> \
  --type=json -p='[{"op":"remove","path":"/data/client-secret"}]'
kubectl -n <app-namespace> rollout restart deploy/<oauth2-proxy-deployment>
```

The next auth-system sync re-hashes and restarts Authelia on its own.

## Configuration

All under `oidcClientSecrets` in `values.yaml`: `targetSecret`, `mirrorPrefix`,
`sourceKey`, `bcryptCost`, `reflectionTimeout`, `clients`, plus the usual
`image`/`resources`/`securityContext`.

## Tests

```sh
uv run pytest          # unit tests: parsing, hash planning, restart decisions
uv tool run black .    # formatting, as CI checks it
```

`tests/test_sync.py` pins a bcrypt hash generated by the Authelia binary itself.
If Python's bcrypt ever stopped verifying Authelia's output, every sync would
silently re-hash and restart Authelia forever; that fixture is what catches it.

The `pyproject.toml` here exists only for pytest and black — at runtime the job
uses the PEP-723 header in `sync.py` via `uv run --script`, so only the script is
mounted into the container.
